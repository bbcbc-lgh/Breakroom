# NPC 配置设计

状态：Approved v1.0，已于 2026-08-02 确认

## 1. 配置目标

`Content/NPCProfiles.json` 是首版新增、删除和修改 NPC 的唯一人工入口。配置只描述角色内容和场景参数，不包含运行中的关系、记忆或忙碌状态。

首发角色全部采用原创虚构形象；角色姓名不表示需要还原任何真实人物外貌。

## 2. 文件结构

```json
{
  "schema_version": 1,
  "content_version": "1",
  "npcs": [
    {
      "npc_id": "zhang_xu",
      "enabled": true,
      "name": "张旭",
      "title": "Python / AI 工程师",
      "personality": ["严谨", "直接", "重视证据"],
      "speech_style": "先澄清问题，再给出简洁、可验证的建议。",
      "background": "负责工作室中的 AI 原型与工程质量。",
      "preferred_topics": ["Python", "智能体", "测试", "架构"],
      "boundaries": ["不声称执行了实际代码", "不访问玩家设备或文件"],
      "relationship_tone": {
        "陌生": "礼貌克制，先确认上下文。",
        "熟悉": "自然交流，可以引用近期话题。",
        "友好": "主动给出更具体的建议。",
        "亲密": "坦诚分享判断与顾虑。",
        "挚友": "亲切直接，但仍保持事实边界。"
      },
      "appearance_key": "engineer_teal",
      "spawn": {"x": 284, "y": 206},
      "wander": {
        "enabled": true,
        "radius": 72,
        "speed": 42,
        "pause_seconds": {"min": 3, "max": 7}
      },
      "ambient_lines": [
        "正在核对一段测试输出。",
        "这个边界还需要再验证一次。"
      ]
    }
  ]
}
```

## 3. 字段规则

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 整数，首版必须为 1 |
| `content_version` | 1 至 32 字符，内容修改时手动递增 |
| `npc_id` | 1 至 64 字符，`a-z0-9_`，创建历史后不得更改 |
| `enabled` | 布尔值；禁用后不出现在场景和 API，但历史保留 |
| `name` | 1 至 20 个字符，可安全修改 |
| `title` | 1 至 40 个字符 |
| `personality` | 1 至 8 项，每项 1 至 20 字符 |
| `speech_style` | 1 至 160 字符 |
| `background` | 1 至 300 字符 |
| `preferred_topics` | 0 至 12 项 |
| `boundaries` | 至少一项，最多 12 项 |
| `relationship_tone` | 五个关系等级必须齐全 |
| `appearance_key` | 必须能映射到 Godot 已有外观资源 |
| `spawn` | 位于场景可行走边界内 |
| `wander.radius` | 0 至 160 像素 |
| `ambient_lines` | 1 至 12 项，每项不超过 50 字符 |

NPC 数量首版建议 1 至 8。超过八名时配置仍可通过后端校验，但 Godot 启动日志给出性能和布局警告。

## 5. 加载与错误

后端启动时完整加载配置。任何以下错误都会阻止服务进入 `ready`：

- JSON 无法解析。
- `npc_id` 重复或格式错误。
- 必填字段缺失。
- 关系阶段不完整。
- 数值越界。
- `appearance_key` 不在 Godot 共享清单中。

错误信息必须包含 JSON 路径，例如：

```text
npcs[1].wander.radius: must be between 0 and 160
```

Godot 读取同一文件时校验展示必需字段。如果配置版本与后端返回版本不同，启动界面显示配置不一致并禁止发起对话，避免姓名与记忆对象错配。

## 6. 修改规则

- 修改 `name`、职业、性格、表达或外观后重启即可生效。
- 不要为已经产生数据的角色修改 `npc_id`；需要全新角色时创建新 ID。
- 删除角色优先设置 `enabled=false`，这样历史仍可审计。
- 改名后旧对话保留当时姓名快照，新对话使用新名称。
- 配置不允许直接写系统提示模板或任意工具定义，防止内容配置越过安全边界。
